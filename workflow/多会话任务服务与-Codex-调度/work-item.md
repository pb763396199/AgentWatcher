# 多会话任务服务与 Codex 调度

## 原始请求

用户已确认 AES Workflow 多会话调度框架设计，并要求“按设计写出施工计划，然后施工”。上游设计位于 workflow/AES-Workflow-多会话调度框架设计/design.md。本任务实施通用服务与 Codex 首版，不把具体 AES 插件源码加入 AgentWatcher。

## 目标

让人和 agent 经同一个持久任务服务管理路线、执行与交付，并让 Codex 独立会话在明确的验收与 Git 版本下可靠推进。

## 范围

- 通用数据库、后台服务、CLI、Codex 运行器与工作流状态管理。
- 项目、路线版本、节点依赖、单执行归属、handoff、评审、人工接受、通知、暂停、改线及恢复。
- Git 工作区、roadmap 集成分支、备份与旧记录选择导入的受控入口。
- CLI 与服务的使用文档、数据库/状态/真实二进制合同测试。

## 强约束

- 按用户要求在 dev 分支施工，保留已有工作区内容，不自动提交或推送。
- 零插件完整运行，不内置具体 AES 插件程序或专有业务分支。
- 现有 session 查询继续直接读数据，不启动任务服务或产生模型用量。
- 任务规模在规划阶段控制；运行期不按上下文 token 数催促交接。
- 默认人确认后才进入下游；仅显式授权可以自动继续。
- 两次无进展触发指定反思，第三次仍无进展暂停并转人。

## 验收条件

- AC-001: SQLite 持久保存项目、路线版本、节点、执行、交付、评审、授权和事件，多个项目隔离。
- AC-002: 工作流 CLI 按需唤起单例服务，查询旧 session 命令不唤起它；退出后可重新收件。
- AC-003: 节点只能被一个有效执行者认领，重复请求幂等，版本和请求内容冲突明确返回。
- AC-004: handoff 主动提交并检查版本、内容和产物；独立评审和人工接受分开记录。
- AC-005: 节点内进展跟进、两次反思、三次暂停，以及持久暂停和回执行为有测试。
- AC-006: 改线发布需要明确确认；受影响节点冻结，旧成果待复核，原归属不因超时重复派发。
- AC-007: Codex 运行器保存 thread/turn 对应关系，服务停止不杀施工；不争抢手工会话写锁。
- AC-008: 受控 Git 准备、候选整合和比较目标更新保护分支；上游代码未就绪不得派发下游。
- AC-009: 备份与恢复核对版本、数据库及产物，旧记录先只读预览，再显式导入。
- AC-010: CLI taxonomy/contract、工作流测试和 headless 构建检查通过。
- AC-011: 界面提供工作流状态与人工操作入口；改界面时运行真实 Tauri 验收。
- AC-012: 保存计划、实现、验证与使用指南，准确标出实测范围与剩余限制。
