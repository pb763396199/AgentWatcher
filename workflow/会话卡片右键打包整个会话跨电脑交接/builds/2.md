# 第 2 轮施工：git 锚点与 README 格式说明

## 做了什么

起因：用户把一个真实交接包（本会话的 ZCode 包）交给另一个 agent 评审，转来评价并拍板取舍。

- `src-tauri/src/lib.rs`：
  - `session_package_git_anchor`：工作区是 git 仓库时用只读 git 命令取锚点（`remote.origin.url`、分支、HEAD、`status --porcelain -uno` 的未提交数、`rev-list --count @{upstream}..HEAD` 的未推送数）；git 不存在或非仓库返回 None，静默省略。
  - manifest.json 增加 `git` 块；HANDOFF.md 在工作区行后增加一行「代码锚点：<repo> @ <branch>（<head 前 10 位>）」，有未推送提交时追加「N 个未推送提交」。
  - 包内新增 `README.md`（`render_session_package_readme`）：十几行数据格式说明——包结构、各 provider 的 raw 口径、SQLite 来源的 `data` 列双重编码提示、`certutil` SHA256 校验方法、快照时点语义；不含任何会话正文。HANDOFF.md 保持极简不变。
- 单元测试：新增 `session_package_records_git_anchor`（临时真实 git 仓库：HEAD 40 位、无远端时 repo null、无上游时未推送 null、manifest 与 HANDOFF 锚点行落盘）；`session_package_manifest_matches_files` 补断言（非 git 工作区 manifest 无 git 块、HANDOFF 无锚点行、README 存在且含双重编码说明、README 无正文）。
- `AGENTS.md`：命令文档同步 git 锚点与 README。

## 哪里没按计划走

- 用户人工验证抓到缺陷：打包时连续闪出大量终端窗口。原因是 `session_package_git_anchor` 拉起 git 子进程时漏了 `CREATE_NO_WINDOW`——GUI 子系统进程每拉一次控制台程序就闪一个黑窗，一次打包 5 个 git 查询就是 5 闪。已按仓库既有 `spawn_hidden` 模式补上 creation_flags 并重验（4 个 session_package 测试通过）。
- 外部 agent 评审建议中的三项明确不采纳（用户拍板，理由进契约设计取舍决策 6）：git bundle/代码进包（代码走 git 正交通道）、工作区文件（模型、构建产物）进包、正文脱敏（破坏全量与 SHA256 校验承诺）。评审指出的"step-finish token 计数为 0"是 ZCode 上游数据问题，不属于打包职责，未处理。
- 本轮未重跑 `test:tauri:flow`：改动是打包产物内容的纯增量（manifest/HANDOFF/README），UI 菜单与命令面未动，由 4 个单元测试覆盖；用户正在用运行中的 dev 实例做人工验证（tauri dev 已自动重编生效）。验收阶段跑流程与冒烟。
