# 第一轮施工：全历史与归档搜索落地

## 做了什么

- `resolve_scan_options`：`active_window_days=0` → `active_window_ms = u64::MAX`；全历史下 `max_sessions` 夹到 20,000、`sqlite_session_scan_limit` 解除到 `max_sessions×3`；`is_full_history` 辅助函数。
- OpenCode/ZCode 扫描：候选行先收集再处理，全历史模式用 `batch_message_counts`（`json_each` 聚合）补齐预算外行的 messageCount；连接打开抽成 `open_readonly_sqlite`，SQL 行映射抽成 `opencode/zcode_session_row_from_sql` 供扫描与定向查找复用。
- Codex zst：候选收集接受 `zst` 扩展名；`read_file_prefix_text` / `read_file_suffix_text` 透明解压（头部流式解够即停、尾部滚动窗口只留 256KB）；`codex_file_base_name` 处理 `.jsonl.zst` 双层后缀的 UUID 提取；`CodexZstDepth` 枚举区分列表 HeadOnly 与定向 Full，HeadOnly 摘要不落缓存（防止薄摘要污染定向查找）。
- `lookup_session_full_history` 定向兜底：zcode/opencode 按 ID 直查行 + 全量摘要（单会话约 18ms）、codex 按 ID 扫文件名定位后全量读、其余 provider 按前缀选 provider 的全历史宽扫。
- CLI：`--include-archived` 参数、`find_session` 两段式、`show --content` / `handoff export` 对 zst 写解压副本（`export_codex_zst_transcript`）。
- 文档：`skill/SKILL.md` 加"时间窗口与归档"一节并修正"只读"声明；`AGENTS.md` 的 ScanOptions、CLI、Codex 数据源三处口径。

## 哪里没按计划走

- 契约初版没有 zst 解压副本这一项：实现中发现 codex `--content` 合同是"给可读的原始会话文件路径"，zst 路径对调用方不可读，补了 `export_codex_zst_transcript`（CLI 层，GUI 不经过）。已并入本轮，取舍记进 contract.md 设计取舍表。
- `sqlite_session_scan_limit` 第一版把全历史上限设为 `max_sessions`，被自己的单测打回（`×3` 裕量被 clamp 吃掉），改为全历史直接返回未夹取值。
